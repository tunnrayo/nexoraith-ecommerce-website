## v0.10 notes for the next Claude session
- PRIVATE DATA RULE: the repository is PUBLIC. Never commit the owner's market (reference) prices, margin rules, `.env*`, databases, backups or customer data. Private prices: `data/catalogue/private/` (ignored).
- Sign-in: admin accounts live in the `admin_users` table (scrypt). `ADMIN_EMAIL`/`ADMIN_PASSWORD` only create the FIRST admin (start-up) or reset one with `npm run create-admin`. Private local values go in `.env.local` (Git-ignored, read before `.env`). Never commit it; never print it.
- `SESSION_SECRET` keys the stored hash of admin session tokens (`security.sessionHash`). Without it the app falls back to plain SHA-256 (works, but the Health Check warns/fails in production).
- Health Centre: `src/health.js` (checks) + `/admin/health` (page). It makes real HTTP requests to the running server on its own port, uses a rolled-back SAVEPOINT for the write test, deletes its throw-away cart, never creates orders. When adding a feature, add a check or test; keep statuses honest (NOT RUN when it was not executed).
- Tests must not read a developer's `.env.local`: `tests/helpers.js` sets SESSION_SECRET/ADMIN_*/TRUST_PROXY explicitly.
- Hosting decision: Railway + Volume (SQLite). Vercel would require a database/storage rewrite. See DEPLOYMENT.md.
- Standing rules still apply: no push to GitHub or deploy without the owner's approval; no live payments/emails; no products outside the approved list.
